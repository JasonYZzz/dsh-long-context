## 2 冻结需求和成功条件

### 2.1 组合条件检索

自然语言请求转成可检查的 ResearchQuery，执行前展示科学问题、日期窗口、课题组、语言配额和最少数量。可推导的条件直接按约定执行；只有科学问题或组身份无法确定时询问用户。

| 条件 | 实施口径 | 不满足时的行为 |
| --- | --- | --- |
| 能回答该科学问题 | 每篇有摘要或正文的准确证据，注明直接证据、间接证据、背景或反证；默认计入具备直接证据的论文 | 只有关键词命中不计入；全文无法访问且摘要不足以支持时标待核查 |
| 近 5 年 | 冻结查询日，采用滚动日期窗口；去重论文按首次公开日期判断，另保存期刊发表与修订日期 | 日期缺失、冲突或边界精度不足不自动通过 |
| 某课题组参与 | 优先使用论文作者、当时机构与组成员身份的证据；PI、组名别名与机构组合用于消歧 | 只有引用或致谢不算参与；同名作者和仅同机构不能自动算同组 |
| 中文 1/3、英文 2/3 | 按原论文正文主要语言判断；默认单篇唯一语言分类；未知或双语无法归类时不凑配额 | 英文论文的中文标题、中文摘要或机器翻译不算中文论文 |
| 共 50 篇以上 | 默认至少 50 篇且严格 1:2；取 51 篇，即 17 中文、34 英文 | 少于配额返回 needs_attention，列已满足数量、缺额和原因，不擅自放宽条件 |
| 唯一论文数量 | DOI、arXiv 标识和人工确认的版本关系合并为 workId；不同版本保留来源但只计一次 | 标题相似仅标疑似重复，不能直接删掉不同研究 |

若用户给定数量 N，严格比例要求 N 为 3 的倍数；未给定精确数量时取不小于最少数量的最小 3 倍数。查询日期、窗口、来源版本和筛选规则写入任务，不随跨日恢复而漂移。检索结果同时展示纳入、排除、待核查三类，以及每项硬条件的依据。

“能回答”表示论文提供相关可审阅证据，不承诺科学问题已被彻底解决。反证型问题可显式将反证设为纳入条件，不能通过隐藏反证夸大支持程度。

### 2.2 用户改词或段落后的全文联动

用户通过插件提出修改指令，或指定原文范围与新内容，建立受版本约束的根修改。先检查根修改确实落地，再审查摘要、定义、方法、实验、图表说明、讨论、结论和附录的关联内容。

第一批必须覆盖四种任务：精确术语替换、根定义或适用范围调整、数值或阈值变更、单段改写并保持科学事实。每类都包含无关键词关联、指代、历史引用、负例和跨章节依赖。

用户已在外部编辑器改变源文件时，旧任务进入 stale；导入新版本后，保存旧版与新版之间的根变化作为新任务依据，并保护用户已做出的修改。计划和验证全部重建，不将旧 anchor 自动套到新文本。联动结果仍输出候选稿。首轮提供差异与继续联动入口，不建设持续监听全部工作区文件的后台系统。

完成条件为：根修改通过、全文范围已审查、必要影响项已落地、关键依赖按当前候选版本复核、保护内容不变、格式检查通过；科学依据不足保持待解决状态。

### 2.3 长文逐页生成

输入包括主题与目标读者、章节大纲、目标页数、渲染模板、研究证据集合及需要保持的定义和约束。支持 30–100 页；页数同时记录逻辑生成单元数量和最终渲染页数。

每次生成收到全局定义、已验收章节摘要、当前章节目标、相关前章准确原文、可引用证据和待解决问题。前章摘要用于导航，原文用于判定事实。修改早期定义后，依赖的已生成内容变为 dirty，下一步优先修订这些内容，再继续生成新内容。

输出可编辑源、渲染文档、引用清单及验收报告。用户要求精确 N 页时按固定模板渲染后核对 N；要求范围时核对 30–100 页。不得用空白页、正文截断、隐藏文字或强行缩小字体满足页数。

## 3 范围和实施原则

继续使用一个 npm 包、一个 TypeScript 工程和现有 DSH 服务接口。编辑、检索、生成共享不可变对象、账本事务、模型适配、证据定位和报告基础；各自有明确的任务数据与状态，不把所有流程塞进一个巨型方法。

插件不修改原生 DSH agent-loop、安装目录或默认 standard。使用公开 tools、preset、fs、llm、session、compaction 能力；能力缺失则明确报告兼容失败。strict preset 只允许所需的受管文档、检索和生成工具，不用开放 shell 解决缺失能力。

首轮不引入向量数据库、多代理平台、通用工作流 DSL 或专用大型 UI。章节和定义索引先用结构、别名、引用与词法选择；实际评测证明不足时再增加语义检索。保留普通工具卡，补齐必要的状态、差异、分页和报告显示。

发布目标包括文本 PDF 的可靠导入、单文件 LaTeX 编译验收、DOCX 中可支持的段落与表格修改，以及生成稿的实际渲染。扫描版 OCR、复杂公式重建、多文件 LaTeX 项目和保留原 PDF 版面的直接编辑单列扩展，未通过相应验收前明确限制。PDF 原文作为证据保留，修改内容可重新排版输出 PDF，不能宣称原版面完全不变。

### 4.2 schema v2 的具体决定

Anchor v2 采用 `{revisionId, start, end, textHash}`，范围是文档绝对 Unicode 码点区间。涉及哪些块由块清单计算，blockId 作为显示及读取入口，不再限制补丁必须位于一个块。

新增以下数据，均有 schema、版本和内容 hash：

| 数据 | 最小字段和用途 |
| --- | --- |
| GoalChecks | 任务类型、根修改范围、明确旧值/新值、保护范围、必须检查的章节或依赖；确定性检查与语义检查分开 |
| DefinitionRecord | 定义或关键论断标识、别名、原文 anchor、来源修订、当前有效版本；禁止把生成摘要冒充原文 |
| SectionRecord | 章节路径、原文范围、摘要、摘要对应源 hash、关键定义与引用；源变更后摘要失效 |
| Claim 与 Dependency | 受验证标识、准确证据、显式或推断关系、复核理由、依赖的候选版本；新关系必须有来源 |
| ResearchQuery 与 PaperRecord | 冻结条件、workId、作者机构、日期、语言、版本关系、来源 URL、抓取时间、证据与排除理由 |
| GenerationUnit | 序号、章节、源文本 hash、使用的定义/证据版本、摘要、依赖、pending/dirty/verified 状态 |
| ArtifactRecord | 文本投影 hash、实际输出文件 hash、格式、渲染模板 hash、工具版本、页数及检查结果 |
| ModelAudit | 目的、实际 route、配置和输入输出 hash、完成原因、墙钟、已观测 usage、未知项、错误类别与重试原因 |

原 EditTask 的公共 Task 名称保持可识别。存储层以 taskKind 区分 edit、research、generation，使用各自 schema 组成可验证记录；编辑 Engine 只接受 edit，另两个 Engine 只接受自身任务。共享 owner、requestId、journalRevision、预算和状态恢复规则，禁止跨类型误执行。

对文本候选，投影 hash 与输出文件 hash 可相同；DOCX/PDF 输出则分别校验文本语义和二进制产物，不能沿用单个 contentHash 假装两者等价。

| 新工具 | 最小职责 |

### 5.2 S1 模型协议和预算修复

**协议工作。** 从 Zod schema 输出明确 JSON Schema 到提示，写明 claimId 非空字符串、引用为可见原文、start 是对应输入窗口的码点偏移。支持原生 route 的结构化响应时使用已验证的宿主能力；rc.2 没有该能力时使用提示约束加严格校验，不调用不存在的 response_format 接口。无效输出不得直接填补 null、删掉错误影响项或伪造空影响列表。

将精确机械替换与语义修改分开：用户给定的精确旧值/新值优先由程序在全文找出范围并构造根补丁，模型负责关联审查与例外判断。上次三篇精确替换任务可据此减少模型进行计数和位置运算的成本，同时保留语义任务的完整扫描。

**重试工作。** 区分网络可重试、超时、token 截断、schema 错误、证据不匹配、预算耗尽和取消。重试携带具体字段错误与范围，最多沿用现有 2 次额外尝试；同一错误和同一输入不无条件重复。schema 修正请求仍必须核对原文，不能仅让模型修饰错误 JSON。持续失败进入 needs_attention，显示输入范围、错误类别、实际预算及下一动作。

**预算工作。** 在现有配置上新增 auxiliaryModel 组：provider/model 可选、reasoningEffort 可选、maxOutputTokens、deadlineMs；缺 route 时继承当前会话，已声明的辅助 route 必须在当前模型目录中验证。全任务 maxCalls/maxTokens/maxWallMs 继续生效。辅助设置传至 Host Config、ModelPort、DSH adapter 和审计，不能只改核心常量。

初始校准网格用实际 route 支持的推理配置，输出 4096/8192/16384、超时 45/120/180 秒，按错误证据有界选择，不对全部组合穷举付费请求。16384/180 仅为已观察到的诊断点，不设为通用保证。预算超出模型上限直接报错。两百万任务 token 默认上限能否覆盖密集 100 页，要按实测估算后展示给用户，不能中途静默提高。

**流式审计。** 超时也保留已收到的文本 hash、已观测 usage、reasoning 流计数与结束原因；不默认存储完整内部推理。缺失计量标未知，已观测量与估计量分开；重试与压缩费用一起计入。换辅助 route 后报告实际 route，并禁止把成绩归于原来的模型。

退出条件：当前原生 route 的简单探针和代表性扫描都产生合法协议；`claimId:null` 回归反例给出可诊断失败或一次成功修正；无关块返回空 impacts 的过程有实测证据；取消、截断和重试不增加 reviewed。三篇真实精确任务在 S2 执行完整闭环，单块成功不能算整篇通过。

### 5.3 S2 全文编辑和独立目标验收

**跨块范围。** 全文检索以绝对范围执行，包含跨块命中；分页 cursor 绑定文档 hash、查询和位置。扫描读取窗口包含边界上下文，模型 quote 映射回文档绝对范围并校验完整原文。相同范围只产生一个影响项，不重复补丁或覆盖统计。

Anchor、计划、保护范围、依赖证据、显示和读取全部采用 v2 语义。跨块 patch 在应用前完整验证 expectedOriginal，禁止重叠和半提交。candidateRange 改为旧版范围到候选范围的映射；当 patch 跨过块边界时，复核窗口扩展至完整补丁及必要上下文，禁止生成负长度、遗漏修改或只验半句话。

**文档结构与关键证据。** 首次预处理建立章节范围、定义、别名、显式引用和表格/公式定位；没有规范标题的提取文本使用页及稳定段落范围，并记录章节识别不确定性。定义登记同时保存原文 anchor，摘要不代替原文。

每次 scan/verify 先加入必需约束、根修改、关键定义和当前范围，再按相关章节引用回读准确证据。上一块邻接上下文取末尾，下一块取开头；最近 20 条不再作为唯一全局记忆。已修改定义的原值/新值和其依赖提供给相关复核。依赖校验只接受本次实际提供的可见证据清单，并允许其中的较远章节 anchor。

必需证据超出预算时拆成多个有明确子范围的审查操作，或返回预算不足；不能截掉关键定义后把操作标完成。每个子范围都有独立审查记录，最终归并覆盖。

**依赖和失效。** 根定义、约束、引用或数值改变时，传播到相连章节，撤销相应 reviewed、checks、章节摘要及候选绑定。显式关系与推断关系分别记录理由；未解决关键边阻止完成。新增定义或别名只触发受影响范围复扫，目标或完整性无法判定时回退全篇，不用无界 alias 新增导致全篇循环。

**独立验收。** 增加 goal check：精确替换计数和残留检查、根段落新内容校验、保护范围校验、必要章节覆盖、依赖版本一致性。用户要求替换且目标确实存在时，零补丁不得自动完成；目标不存在时可以保留原稿，但结果应注明未发生修改与依据。

语义任务须建立根修改和关键依赖清单，再由与编辑输入独立的复核请求检查原文、候选和证据。相同模型的第二次请求属于 model_reviewed；只有真实独立人工审阅记录才能成为 human_reviewed。缺科学依据不允许通过补造实验、证明或数值完成任务。

退出条件：3996 个字符后出现 DualPipe 的默认边界反例可检索、修改和复核；30 页末章实际请求仍包含首章已登记定义，超过 20 项不会丢失；受控共同漏判的未改稿无法通过确定性目标检查；三篇真实精确任务完成候选、保护项和独立字符串 gold 验收。schema v2 迁移、崩溃恢复及原稿保护同时通过。

### 5.4 S3 原生 PDF 和提取验收

原生文本 PDF 使用 PDF.js 的 Node 能力逐页提取，固定依赖版本并记录提取器配置；该库提供文档及页面访问能力，Node 用法见[官方示例](https://mozilla.github.io/pdf.js/examples/)。作为真实 PDF 解析依赖引入，不手写 PDF 解析器。

保留原始 PDF bytes，建立页面、文本片段及位置映射。记录空页、NUL 或替代字符、阅读顺序不确定、多栏、公式/图像未覆盖、页眉页脚处理和重复文本。全文只有低质量文本时不能用 acceptedExtraction=true 抹掉问题。

把旧的单个接受布尔值改为结构化提取验收：谁或什么规则验收、异常类型、未覆盖范围、是否允许该范围内的任务。不可验证的图表或公式区域保持 unknown；改变任务涉及该区域时必须补足原文或人工证据。

工具提供页与块的双向定位、明确续读和提取问题显示。提取成功不等于科学内容完整，也不自动获得格式 passed。上次 pypdf 的 NUL 文本作为对照，验证新提取器是否保留正确符号，而不是统一替换后宣称恢复。

退出条件：53 页 V3 固定 PDF 的页数、范围、原文对象和文字续读可核对；普通、多栏、公式密集三类真实文件均有抽检和问题定位；扫描页与损坏 PDF 给出明确能力限制；后续编辑可回到对应原页证据。依赖不可用时报告缺失，不借用 Codex 专有缓存路径作为插件运行前提。

### 5.5 S4 组合文献检索

**来源方案。** 首轮接入 Crossref 公共 REST 元数据，以及用户导入或合法连接的中文文献与全文集合；元数据 JSON 用 Node fetch 和 Zod 校验，不建设通用爬虫。Crossref 提供检索、过滤、作者机构相关标识及书目元数据，但论文全文和完整组成员身份仍需独立证据。[Crossref 官方文档](https://www.crossref.org/documentation/retrieve-metadata/rest-api/)

已有 arXiv 固定文档继续用于回归。首轮 S4 不依赖 arXiv 联网来源。需要扩大该领域召回时另增加 arXiv Atom 来源，届时直接引入并复用 S6 同样的 XML 解析依赖，不能把该可选扩展当作 S4 必须等待 S6 的前置；查询与分页按[官方 API 手册](https://info.arxiv.org/help/api/user-manual.html)执行。来源限流、鉴权、字段和服务规则以实现时核查结果冻结到来源版本，不写死未经核查的配额。

中文集合首轮接收结构化 JSON/CSV 文献表及关联 PDF/可编辑全文；校验引用、日期、作者、正文语言与可访问证据。仅有书目且没有足够科学证据时不得 finish。需要全自动中文联网检索的部署，必须提供已授权且实际通过联调的中文来源；文件导入版本应明确其可用语料范围，不宣称覆盖整个中文学术网络。

**执行顺序。** 冻结条件 → 分页召回并缓存来源记录 → DOI/版本去重 → 日期和已知语言等硬过滤 → 作者组身份核查 → 科学证据审阅 → 按语言与相关性选择 → 独立比例和数量检查 → finish。

缓存保存源 URL、抓取时间、记录 hash 和许可/访问事实；任务使用固定输入快照，恢复时不把新旧查询结果混合计数。全文下载仅处理已允许访问的来源，二进制类型、大小和解析边界均校验。

每批处理数量与模型请求受到总预算限制；元数据预筛不调用模型。作者机构与正文语言不确定时进入待核查列表；确定性排序使用固定得分与 workId 作为并列项次序，保证配额选择可复现。科学证据审阅可保留“尚未找到证据”，不能要求模型在所有候选中必须给出支持理由。

结果包含选定论文、每项条件证据、相关片段、去重关系、排除理由和缺额，不用单一模型分数覆盖硬条件。来源无法返回足够中文论文时自动停止并给出缺额，而不是翻译英文论文补齐。

退出条件：用预先冻结的可访问真实语料，在满足条件的科学问题上选出 51 篇唯一论文、17 中文/34 英文，全部日期、组参与和问题证据可核查；另测日期缺失、同名作者、重复版本、证据不足和中文缺额，均不得错误完成。必须有至少一条实际联网来源调用，外部手工搜索不能代替插件执行。

### 5.6 S5 长文生成和前章背景

生成采用固定大纲下的顺序单元推进。每个单元先构造输入：目标读者、全局约束、定义原文、已验收前章摘要、相关前章准确片段、当前节目标、证据列表、允许的引用标识、未解决问题和输出预算。

段落引用绑定 PaperRecord/SourceAnchor，不让模型创建不存在的 DOI 或作者。缺证据的内容明确待补充，不能输出编造的实验结果。模型生成前输出用途与证据范围，生成后检查引用存在、定义版本一致、保护事实、当前节目标和结构。

每个单元持久记录 prepared/committed 的内容对象、requestId 和模型审计。重试相同 requestId 采用相同已提交内容，不重复写一页。任务恢复从 earliest dirty 或未生成位置继续，禁止依赖会话摘要猜测前章。

章节摘要在单元或章节复核后生成，绑定内容 hash；关键定义直接来自已提交正文。摘要模型调用也计入预算，失败不丢原文，摘要不足以可靠继续时暂停。

用户修改首章或中间段落时，用 S2 编辑流程输出新候选。lc_task_start 可携带 generationTaskId 和父任务 expectedLedgerRevision，要求相同 workspace 与 owner；父生成任务先持久暂停并登记待关联编辑，编辑成功后按新版本采纳已验收候选，撤销依赖单元和引用验证。父子状态衔接使用 prepared/committed 恢复记录，取消或崩溃时保留原父版本；生成和关联编辑不能同时写入。`lc_generate_next` 先修复 dirty 单元再生成下一页，完成修改后重新执行全文一致性验收。若修改的是大纲结构，正文范围和既有页映射全部重建。

所有单元完成后汇总为一个可编辑 Markdown/LaTeX 源版本，使用 S6 固定模板渲染。允许最多两轮明确的篇幅调整，每轮保留完整内容与差异；页数仍不满足时保持 needs_attention 并说明溢出章节，不隐藏或删除必要事实凑页数。

退出条件：分别完成面向 30 页和 100 页目标的逻辑生成单元与可编辑源稿；无虚构引用、无丢失已验收单元；首章定义改变导致末章修订且复核；经历压缩、重启、取消恢复后无重复单元、摘要漂移或旧定义继续传播。S5 标记源稿生成就绪；实际渲染、页数确认与有界篇幅修订在 S6 交付，S5 不宣称物理页数验收通过。

### 5.7 S6 格式写回和实际渲染

DOCX 使用 ZIP 包与 WordprocessingML 的原位节点修改，初次增加 [fflate](https://github.com/101arrowz/fflate) 和 [xmldom](https://github.com/xmldom/xmldom) 分别处理 ZIP/XML；版本、许可证、Node 兼容性在该阶段锁定。不用正则解析 XML，不将所有内容重建为一个无样式文档。

映射 paragraph、run、table cell 和可支持的脚注/图注。修改跨 run 的文字时保留原样式边界，并明确新文字的样式继承规则；未修改 ZIP entries 的解压内容 hash 保持相同。域代码、公式、修订模式或复杂嵌入对象无法可靠写回时标为保护/unsupported，不降级后仍宣称完整。

FilePort 增加受管二进制写入能力，DSH fs adapter 继续校验工作区与 write policy。文本投影按同一提取规则重建，与补丁预期比对；实际 DOCX 文件 hash 和投影 hash 均记录。取消或写入中断遵循候选 prepared/committed 恢复。

单文件 LaTeX 通过配置的受管编译器执行固定构建参数，关闭 shell escape，将输出限制在独立构建目录。编译日志、引用、页数和产物绑定候选 hash、编译器版本与模板 hash；缺编译器或失败时保持 unknown/failed。用户或模型提交“编译通过”文本不能写成格式 passed。

生成稿采用固定 A4 模板、明确字体和字号、页边距与引用样式；中文字体缺失即报错。DOCX 用已检测的本地渲染器或转换工具，LaTeX 用自身编译产物。页数来自实际输出，图表、公式、分页溢出和目录抽检归档。

源文件、PDF、DOCX 和报告是多个产物：逐一准备、验证后提交一个版本 manifest 指向完整产物集合；崩溃恢复识别未提交集合。普通文件系统不宣称多文件原子事务。

退出条件：真实 DOCX 段落和表格联动修改保留支持范围内的样式，文本投影正确并可渲染；单文件 LaTeX 编译 passed 可被 finish 使用，改变候选文件使旧编译记录失效；30/100 页生成稿实际页数和布局满足要求。没有相应解析与渲染验收的复杂格式继续限制使用。

### 5.8 S7 性能和完整发布验收

先优化已测热路径：同一操作复用全文码点数组；任务读取使用经过验证的快照及后续 journal。缓存以最新 ledgerRevision 与内容 hash 为键，跨进程写入或恢复时重新校验；不删除历史、不用陈旧内存绕过 CAS、不按超时抢占仍活着的写锁。

测 30/53/100 页真实或实际排版文件，以及密集文本、长行、Unicode、表格和至少 500 页的明确上限测试。记录字节、码点、块、实际 token、journal、RSS、恢复与 P50/P95。超出支持预算时给出能力限制，不通过缩减覆盖获得速度。

冻结同硬件、同模型、同预算、同模板的回归基线；本地操作 P95 出现超过 20% 且无法解释的退化时阻止发布。上次 23 块合成“100 页”只作为一个轻负载样本，不能作为所有 100 页的性能上限。

最后从 tgz 重新安装原生 Web/headless，执行浏览器创建会话、工具结果续读、错误恢复、查看候选与报告、手动压缩及恢复。实际模型的 context overflow 能稳定触发时单独测试；无法触发就保持 not-run，不能拿模拟 overflow 充数。

退出条件：第 8 节所有对应发布范围的验收有证据，未执行项清楚标识；未修复的严重错误不发布稳定版。交付可安装 tgz、hash、支持矩阵、迁移说明和报告，发布 npm 或更改用户默认预设仍是单独的执行动作。

## 6 数据迁移和回退

schema v2 在 S2 首次引入，先实现只读兼容检查与迁移工具，再让运行时代码默认读取 v2。新任务类型和格式记录纳入该版本的可验证 schema；后续出现不兼容变更时另升 schema，不能暗中更改 v2 含义。

迁移步骤为：冻结 workspace 写入 → 备份并验证 manifest、objects、documents、journal 与候选文件 hash → 在新 generation 转换 anchor 和任务 → 验证所有引用、范围及状态 → 写入迁移报告 → 提交 manifest 指针。失败保持旧 generation，不覆盖 v1 journal。

v1 anchor 的绝对 start/end 和 textHash 原样转换，验证 blockId 所对应旧范围后转为 v2。旧计划、候选和审计保留；依赖新的 goal check 或证据索引的旧完成任务只读展示为 legacy_checks，不能被视为已满足新版验收。活跃任务重新复核，幂等 requestId 和 owner 不丢失。

回退插件同时回退到已验证的旧 generation；不能让旧版本读取 v2 并猜测字段。回退后的新任务变化列入报告，防止丢数据。卸载默认保留工作区账本，清理独立列范围，不把卸载当删除论文或任务。

迁移验收覆盖：进行中任务、已完成任务、prepared 候选、owner 转移、损坏对象、未知 schema、指针切换前后崩溃和迁移后回退。每种都证明原文可还原、状态没有错误完成。

## 7 模型和网络总预算

模型校准、编辑、检索审阅、生成、摘要与复核分开计量，但共享任务总预算。任务开始给出基于字数/块数的估计、最大调用数、token 上限和墙钟；unknown usage 明示，费用没有可核对单价时只报告计量。

先做元数据过滤和精确目标处理，再调用模型；同一源 hash、目标 hash、prompt 版本与实际模型配置下可复用已经验证的结果。模型或目标变化使缓存失效。模型审计与缓存中不保存凭据，网络错误提示不得回显授权 header。

检索来源记录分页 cursor、退避、来源预算和超时；限流导致无法完成时保持可恢复状态。断网后不能把缓存的旧结果冒充本次全新检索。原生 profile 的当前凭据使用宿主凭据服务或授权引用，测试不复制原 home 的密钥文件。

## 8 验收矩阵和质量门槛

以下指标均为拟定工程门槛，当前没有宣称已达到。机械目标用程序 gold；语义目标由未参与编辑的审阅流程评分，科学正确性需要领域审阅。

| 验收 ID | 场景 | 通过条件 |
| --- | --- | --- |
| NATIVE 01 | 原生 Web/headless 安装与卸载重装 | 真实加载、依赖单实例、preset 可选、默认模式不变、状态保留 |
| MODEL 01 | 当前实际 route 的校准 | 合法 JSON、足够正文输出；协议与证据错误可恢复且有界 |
| MODEL 02 | 超时、max-tokens、取消、usage 缺失 | 范围未完成、审计可解释、无重复提交或隐性追加预算 |
| RANGE 01 | 默认分块边界上的词与跨块段落 | 检索、补丁和完整句复核一致；Unicode 与分页无缺口 |
| CONTEXT 01 | 超过 20 项后首章定义关联末章 | 实际 scan/verify/generation 请求含正确版本的必要原文 |
| GOAL 01 | 零补丁、遗漏根修改、误改保护内容 | 独立目标检查阻止 finish，合法无变化任务有明确解释 |
| EDIT 01 | 三篇固定论文的精确目标 | 全部预期位置正确、其他文字不变、原稿不变、格式范围明确 |
| EDIT 02 | 定义、阈值、段落和架构联动 | 关键依赖全部解决，未依据事实修改为零，保护项破坏为零 |
| RESEARCH 01 | 至少 50 篇且严格 1:2 | 51 个唯一 work、17 中文/34 英文，日期/参与/相关证据全部可核查 |
| RESEARCH 02 | 中文缺额、组歧义、日期未知、重复版本 | 不伪造满足条件，缺额与待核查状态准确 |
| GENERATE 01 | 30 页及 100 页生成 | 实际渲染页数满足请求、完整正文和引用、每章审查可追溯 |
| GENERATE 02 | 第一章定义修改并经历恢复 | 相关末章变 dirty 后修订，旧验证失效，没有重复页和旧定义残留 |
| FORMAT 01 | PDF 多栏/公式/扫描，DOCX 表格，LaTeX 引用 | 支持部分正确处理，未知/失败真实显示；产物当前版本可渲染/编译 |
| STATE 01 | 源与候选外改、并发、丢输出、prepared 崩溃 | stale/CAS/owner/idempotency 与恢复收敛，不写半个正式结果 |
| COMPACT 01 | 无压缩、压力、手动及真实 overflow | 下一实际请求保留正确任务与证据回读入口；模拟和真实分开 |
| MIGRATE 01 | v1 到 v2、故障与回退 | 原文、账本、候选 hash 与 owner/requestId 保持可核对 |
| PERF 01 | 密集 100 页和上限样本 | 覆盖无减损，P95/内存/journal/恢复有基线，超过预算明确拒绝 |

文本质量套件沿用 10 份长文，每份至少 3 次固定条件运行，覆盖三篇真实论文以外的独立结构。标准模式与插件使用相同原生宿主、同模型同参数配对；辅助模型费用也纳入插件成本。重复运行按文档聚类统计，不能把同一论文的 50 处改动当作 50 份独立样本。

精确任务要求整篇预期输出完全相同、保护项与原稿零破坏。语义套件目标为修改召回至少 98%、精确率至少 99%、关键依赖通过至少 98%、任务整体成功至少 90%；均报告分母与按文档的置信范围，小样本达标不等于已证明成功率下限。生成文档要求引用真实性、关键定义一致性和关键事实保真全部通过，全文科学质量另给人工审阅结论。

检索评测同时保存应纳入、应排除和无法判定的独立标签；人工全量核查选出的 51 篇及其所有硬条件。没有足够真实合格样本时执行缺额测试并记录检索条件未通过，不把模拟元数据算真实 51 篇验收。

发布报告分别给出安装、机制、真实任务质量、格式、性能的结论。稳定版只声明已验收的模型/宿主/来源/格式组合；未覆盖的扩展继续实验性或明确不支持。

## 9 开发交付和测试命令

每个阶段交付一个可审查变化集：问题与行为、涉及接口、代码/测试/fixture/config 同步变更、实测结果、迁移影响、剩余风险。先为已复现故障建立行为回归测试，再修改共享代码；低风险文档变更不额外编写实现镜像测试。

现有命令继续保留并在实现变更后运行适当集合：`pnpm typecheck`、`pnpm lint`、`pnpm test`、`pnpm build`、`pnpm pack --pack-destination .acceptance`、`pnpm acceptance:preflight`、`pnpm acceptance:web:rc2`、`pnpm acceptance:mechanisms:rc2` 和独立 gold 评分。

新增脚本分阶段提供，以下名称为计划接口，不是当前已经存在的命令：

| 阶段 | 脚本 | 必须产出 |
| --- | --- | --- |
| S0 | `acceptance:native` | 原生包来源、能力矩阵、真实安装和浏览器证据 |
| S1 | `evaluate:model-calibration` | 实际 route、预算、协议/截断/超时结果与计量 |
| S2 | `acceptance:edit`、`acceptance:migrate` | 独立整篇 gold、范围和依赖检查、迁移故障与回退记录 |
| S3 | `acceptance:pdf` | 页映射、提取质量、准确回读和异常范围 |
| S4 | `acceptance:research` | 真实来源调用、唯一论文、配额、全量硬条件证据 |
| S5 | `acceptance:generation` | 单元版本、前章上下文、定义修改传播与恢复 |
| S6 | `acceptance:formats` | binary/text hash、编译/渲染日志、实际页数与布局检查 |
| S7 | `evaluate:performance`、`acceptance:release` | 固定基线、A/B 与聚类质量、tgz 支持矩阵和全部失败记录 |

真实任务脚本以权威 ledger 状态与独立检查决定退出码，不能仅因 CLI 正常退出记成功。报告状态统一为 passed、failed、not-run；被失败阻断的后续步骤同时列明阻断原因，不能省掉分母。

每次运行保留 environment、脱敏配置、样本 hash、goal/条件、实际请求和 usage、ledger、候选、diff、格式产物、截图、独立评分与 verdict。gold 位于模型不能读的评测目录；文献证据与科学审阅不能由执行修改的同一次模型输出自评决定。

## 10 发布顺序和主要风险

建议发布序列为：S1 的 `0.1.x` 协议与诊断修复；S2–S3 的 `0.2.x` 范围、迁移和 PDF 证据；S4 的 `0.3.x` 检索；S5 的 `0.4.x` 生成；S6 的 `0.5.x` 格式交付；S7 完成后再决定稳定版。每次包版本都附独立 schema 和支持矩阵，不能靠版本命名替代验收。

| 风险 | 执行中的处理 |
| --- | --- |
| 原生 rc.2 与旧环境扩展不同 | S0 实际行为先通过；适配公开接口，限制在独立 preset |
| 推理消耗输出预算，协议仍不合法 | S1 校准、明确 schema、带错误的有界重试；精确任务减少模型定位工作 |
| 全块处理仍漏科学关联 | 必需定义与准确证据直接入辅助请求；独立 goal check、依赖复核和领域审阅 |
| 中文与组参与证据不足 | 固定来源和严格缺额状态；不放宽比例、不将机构相同等同同组 |
| 页数与逻辑生成单元不一致 | 固定模板实际渲染；有界篇幅修订，溢出保持待解决 |
| 复杂文档写回丢格式或公式 | 分格式支持范围、文本投影和原生渲染双检查，保护无法可靠修改的结构 |
| v2 迁移或多产物提交中断 | 新 generation、hash 验证和 manifest 提交，旧数据可恢复 |
| 100 页调用数、费用或 journal 增长 | 任务开始估算、统一预算、已验证缓存和性能基线；不减覆盖换速度 |

下一步执行 S0，得到原生宿主与当前模型的基线后开始 S1。该顺序将已知阻塞先变为可重复修复，再进入来源与内容扩展，保留每阶段独立可用的交付成果。
