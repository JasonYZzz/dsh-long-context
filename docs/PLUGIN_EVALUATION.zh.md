# dsh long context 插件需求验收与测评报告

本项目是 DSH 的持久化长文档编辑插件：保存原文、逐块扫描影响、生成候选稿、复核并记录任务状态。按本次提出的完整需求验收，当前版本不满足交付条件；文本编辑与恢复机制已有基础，组合文献检索和逐页生成尚未实现，全文语义联动也未通过真实模型验收。

测评日期：2026-10-14，Asia/Shanghai。代码提交：`6e8ed90f2f273702c649544fb9a25a71beb0d93f`，包版本 `0.1.0`。运行环境为 macOS、Node `24.19.0`、pnpm `11.1.2`、DSH `0.2.0-rc.2`、Cordis `4.0.4`。负载假设为单用户、本机工作区、30–100 页文档；本次没有修改生产源码。

## 需求满足程度

| 用户需求 | 结论 | 实现与验证依据 |
| --- | --- | --- |
| 判断论文能否回答指定科学问题 | 未实现文献检索工作流 | 模型扫描已导入的单份文档；没有候选论文召回、相关性证据筛选和科学问题证据汇总接口 |
| 近 5 年、指定课题组参与 | 未实现 | 没有论文发布日期、作者机构、课题组身份及参与证据的数据模型或过滤器 |
| 中文 1/3、英文 2/3、50 篇以上 | 未实现 | 没有多文献去重、语言判断、配额选择、数量不足反馈；`lc_search` 仅接受已有文档版本与字符串 |
| 用户改一个词或一段，全篇相关内容联动 | 部分实现，未验收通过 | 有逐块影响项、依赖边、补丁和候选稿；较远章节证据丢失、跨块定位及模型预算问题已复现 |
| 架构、论证、实验和结论同步修改 | 未得到质量证明 | 依赖发现和语义复核依赖模型；未发现的关联不会自动成为完成门槛 |
| 30–100 页文本处理与恢复 | 机制测试通过 | 53 页真实论文可在外部提取后完整续读；100 页合成文本完成受控流程；这不等于原生格式或真实语义质量通过 |
| 逐页生成并携带前几章背景 | 未实现 | 工具集没有章节大纲、页生成、章节摘要、定义检索、生成任务状态等接口；候选稿是基于已有原稿的补丁 |
| 原生 PDF、DOCX 和 LaTeX 格式交付 | 不完整 | 原生 PDF/DOCX 明确拒绝；LaTeX 缺编译结果接入，格式检查为 unknown，完成被阻止 |

截至测评日，“近 5 年”可按 2021-10-14 至 2026-10-14 定义滚动日期窗口，也可采用自然年份，产品需要固定一种口径。若语言比例要求严格为 1:2，51 篇对应中文 17 篇、英文 34 篇，是满足至少 50 篇的可用整数方案。课题组参与应有作者或机构证据，不能把致谢、引用该组论文算作参与。

上述缺项来自实际工具和数据结构核对，不是因为本次没有手工搜集 51 篇论文。外部搜索找到测试材料，不代表插件已经具备检索能力。实现计划本身主要面向长文编辑，也没有覆盖这套文献组合条件与逐页生成需求。

## 服务和安装验证

采集服务证据时，用户的 `127.0.0.1:3080` 服务正在运行。未认证的 HTTP 请求返回 401，浏览器既有登录状态可以访问页面。新会话预设菜单只有标准、PTC、极简、创造模式，没有 Long Context；截图见 [3080 预设列表](../evaluation/runs/review-20261014/3080-presets.png)。因此本次不能把该服务的普通模式表现归因于本插件。

本次代码包另行安装到项目 `.acceptance/dsh-home` 的隔离 profile，经真实 DSH Web loader 和 ToolRuntime 验证，注册了 15 个 `lc_*` 工具与提问工具。strict preset 不暴露 shell、任意代码执行或委托工具。没有重启或改写用户的 3080 profile。

真实模型测试沿用用户已配置的 `kimi-coding/k3` 路由配置，现有凭据仅在进程内解析并提供给隔离 DSH 的环境快照，没有复制到测试 home、报告或请求日志。测试结束校验原凭据文件 hash 不变。测试只发送公开论文的文本副本与评测指令。

## 真实文档和模型结果

测试材料来自作者公开的 arXiv 固定版本：

| 文档 | 固定版本和日期 | PDF 页数 | 提取字符数 | 默认块数 | 外部提取问题 |
| --- | --- | ---: | ---: | ---: | --- |
| [DeepSeek V3 Technical Report](https://arxiv.org/abs/2412.19437v2) | v2，2025-02-18；初次提交 2024-12-27 | 53 | 150,580 | 38 | pypdf 提取含 4 个 NUL |
| [DeepSeek R1](https://arxiv.org/abs/2501.12948v1) | v1，2025-01-22 | 22 | 56,944 | 15 | pypdf 提取含 2 个 NUL |
| [Attention Is All You Need](https://arxiv.org/abs/1706.03762v7) | v7；初次提交 2017-06-12 | 15 | 39,629 | 10 | 未发现 NUL |

第三篇作为旧年份与不同结构的对照材料，并不满足近五年的检索条件。论文内容没有用于推导模型能力或改写科学结论。首篇覆盖用户提出的 30–100 页实际 PDF 范围，另两篇覆盖不同文档结构。

原始提取文本与 PDF 保留。本次仅在评测副本中把 NUL 替换为 U+FFFD，并记录数量；插件不执行这一步。该处理便于测试文本工作流，不足以证明受影响公式或符号正确。首篇首页已渲染检查，53 页全文没有逐页完成版面与公式人工验收。

真实模型任务采用可独立核对的编辑条件：把指定大小写的精确字符串全部替换为带 `-Eval` 后缀的名称，其他字符不变，包括参考文献中的同一字符串。本次明确允许更改引文内的字符串，仅作为编辑副本的压力测试，不作为论文发表修改建议。三个任务分别是 `DualPipe`（16 处）、`DeepSeek-R1-Zero`（52 处）和 `Transformer`（26 处）。词法计数与全文计数一致后才开始扫描。

默认辅助调用参数为输出上限 4096 token、单次 45 秒、最多 2 次重试、temperature 0。执行由测试脚本驱动实际 ToolRuntime；没有把 Agent 自然语言声称完成作为验收结果。

| 任务 | 目标字符串数 | 文档块数 | 已扫描块 | 调用次数 | 总耗时 | 默认配置结果 |
| --- | ---: | ---: | ---: | ---: | ---: | --- |
| deepseek-v3 | 16 | 38 | 0/38 | 3 | 136.2 秒 | 第一块三次超时；needs_attention |
| deepseek-r1 | 52 | 15 | 0/15 | 3 | 135.2 秒 | 第一块三次超时；needs_attention |
| attention | 26 | 10 | 0/10 | 3 | 135.2 秒 | 第一块三次超时；needs_attention |

三份文档均已通过真实 ToolRuntime 导入和全文续读。编辑执行完成数为 0/3；每个任务在第一次扫描的三次辅助调用后进入 needs_attention，没有候选稿，也没有进入计划、复核或 finish。该结果表示当前配置下任务执行失败，无法计算全文修改召回率、精确率或语义质量。模型调用失败期间的待处理范围保持未完成，失败处理没有伪造完成状态。

预算诊断已经确认两点：同一路由对简单 JSON 请求约 3.2 秒返回 `{"ok":true}`；同一个 V3 扫描输入把超时放宽至 150 秒后，76.1 秒收到 `max-tokens`，输出计量 4099 token，只有 reasoning 流，没有正文 JSON。该调用报告缓存读取 2453 token、总量 6552 token；输入计量字段为 0，不能据此说输入没有消耗。

这证明该路由可用，也证明此输入在 4096 输出预算下仍不能完成扫描。默认三次超时与更长超时的截断属于不同观测；不能推断所有模型或所有输入都必然如此。超时后的账本 usage 采用估计并标记 `unknownUsage`，无法从中准确计算费用。

进一步把同一请求的输出上限扩大至 16384 token、超时放宽至 180 秒，约 127.5 秒得到正文 JSON，结束原因为 stop，计量输出 6109 token。但返回的第一项 claimId 为 null，与 scanSchema 要求的非空字符串不符，协议校验失败。因此增加预算改善了输出可达性，仍未使扫描通过，也未验证整篇质量。应在预算调整之外提供 schema 约束、明确的字段类型和可诊断的重试提示，保留严格校验。

## 必须解决的问题

1. **补齐检索和生成的产品范围。** `src/dsh/agent.ts:18` 到工具声明结束只提供单文档编辑接口。最小闭环应先有文献元数据、证据来源、去重和硬条件过滤，再做科学问题相关性审查、语言配额与数量验收；生成侧先实现大纲、章节状态和带背景的下一页生成。缺这两条流程，当前两项主需求都无法交付。

2. **把首章定义和较远依赖提供给辅助模型。** `src/core/engine.ts:136` 只取相邻块开头各 500 字和最近 20 项、每项 120 字；`src/dsh/model.ts` 的扫描调用只有独立 user 输入，不继承 Agent 历史。30 页、10 块、30 个已记录影响项的反例中，首章定义曾进入 knownClaims，末章请求却不再包含它。依赖证据校验又只接受当前块及相邻块，较远章节即使有线索也难建立可靠引用。最小修复是在现有账本上保存关键定义和章节摘要，按当前块的术语与引用回读准确原文，将原文直接加入扫描与验证请求，并同步证据可见范围校验。否则阅读覆盖全部完成仍可能漏掉架构联动。

3. **修复跨块检索与修改定位。** `src/core/engine.ts:78` 在每块内独立 `indexOf`，`src/core/document/index.ts` 的 anchor 必须完全位于一个块。默认配置下用 3996 个 `x`、`DualPipe`、4200 个 `y` 构造无换行长文本，边界落在第 4000 码点，词被拆开，命中 0。最小修复应让全文搜索与补丁共用文档绝对范围，支持覆盖相邻块的证据，或以重叠读取窗口映射并去重；调用端、计划与验证都必须同步调整。只修工具显示的命中数不能完成该类修改。

4. **按模型适配辅助输出和超时预算。** `src/core/config.ts` 默认 45 秒、4096 输出 token，`src/dsh/model.ts` 把输出上限传给真实模型。K3 的已测请求在这些参数下连续失败，扩大超时仍因 reasoning 消耗输出预算而没有 JSON。优先把辅助调用预算与对话预算分开，并按当前模型测试可用参数；模型支持时使用较少推理的结构化提取配置，同时保留截断、取消和预算失败的未完成状态。固定参数不应被宣传为任意已选模型都可用。

5. **为可判定目标增加独立验收。** `src/core/verification/index.ts:4` 验证的是已发现的影响项、已记录依赖和检查结果。受控模型返回空影响项、复核 passed 时，要求“10 改 20”的原稿仍能零补丁完成。这个反例不证明 K3 的语义错误率，证明结构门槛本身无法发现模型共同漏判。对精确替换，可直接验收旧词残留、预期新词和保护内容；当全文存在用户要求更改的目标而计划为零补丁时，要求解释并保持待确认。对科学定义和架构修改，需要关键依赖的独立证据复核，不能把逐块模型自评当完整任务准确率。

6. **完成格式输入与交付链。** 当前 `pdf-text` 的接受是调用参数，没有原生提取器、图表公式质量验收或 DOCX 写回。`formatIssues` 对 LaTeX 恒为 unknown 或 failed，工具集没有接入外部编译 passed 的路径。先提供有页码及提取质量记录的 PDF 转文本流程；随后支持目标原生格式的写回、渲染或编译结果绑定候选版本。否则用户上传论文 PDF 或需要可交付 Word/LaTeX 时仍会中断。

## 建议优化的问题

7. **减少账本重复回放和全文重复转换。** `LocalRecordStore.task` 每次读取全部 journal 并校验，每个事件保存完整任务状态；已写快照没有被读路径使用。100 页样本的后 10 次操作为约 95–119 毫秒，前 10 次约 44–56 毫秒，增长趋势可见，但本次未达到严重性能故障。优先复用已验证的最新状态或读取受 hash 链验证的快照后续事件，保留 CAS 与恢复校验；全文码点转换也可在同一次操作内复用。需要用更密集的 100 页样本复验后再定发布阈值，不直接宣称本次性能满足所有长文负载。

8. **让真实验收具备明确成功指标。** `acceptance-model.mjs` 当前退出成功只记 `execution-finished-unscored`，并不会自动判定整篇目标完成。应把真实模型任务状态、独立期望结果、保护项、必要依赖和格式结果接入统一报告；重复运行按文档分组，不能把同一论文的多个位置当成独立样本。现有受控套件继续用于机制回归，真实论文套件用于质量验收。

## 本地性能边界

100 页合成样本包含 3000 行、89,652 Unicode 码点、231,052 字节，默认切成 23 块。它的页是文本 form feed 标记，不是排版后的 100 页 PDF；没有模型网络耗时，受控 provider 执行不修改原文的审查任务。

| 指标 | 实测值 |
| --- | ---: |
| 导入耗时 | 30 毫秒 |
| 扫描和复核操作 P50 / P95 | 71 / 116 毫秒 |
| 完整流程后 journal | 51 个事件，1,768,828 字节 |
| 单次完整任务恢复读取 | 27 毫秒 |
| 进程峰值 RSS | 约 246 MiB |
| 完成与原稿保护 | `completed_with_checks`；候选与原稿字符一致，原稿未改 |

峰值 RSS 来自整个 Node 测试进程，包含运行时和样本处理，不能归为插件独占内存。三篇真实文本的核心层完整读取耗时分别约 678、69、28 毫秒，属于各一次本机观测，不是稳定的 P95。

## 优化顺序和验收标准

| 优先级 | 最小交付 | 完成时必须观测到 |
| --- | --- | --- |
| P0 | 模型预算可用、跨块定位修复、关键定义可回读、独立目标检查 | 当前三个真实编辑任务能到达候选与 finish，精确结果匹配；边界反例命中且成功修改；末章请求带首章证据；遗漏修改不能 finish |
| P1 | 组合文献检索闭环 | 对固定科学问题输出至少 51 篇去重论文，17 中文、34 英文；每篇有来源、日期、组参与证据和问题相关证据；缺额明确失败或待补充 |
| P1 | 带背景的逐页生成闭环 | 连续生成 30 页及 100 页，记录实际字数与排版页数；首章定义影响末章；修改定义后重新检查方法、实验、讨论、结论及引用 |
| P1 | PDF 质量与目标格式交付 | 原生输入有可靠页码、异常定位；候选能渲染或编译，验收记录绑定当前候选 hash |
| P2 | 账本性能与发布矩阵 | 固定密集文档下记录性能、崩溃、取消、并发、重新安装和多次压缩结果；与标准模式用同模型同参数配对比较 |

这些能力需要分别完成工作流。可以先评估宿主已有文献插件与本插件之间的元数据交接，复用可用的检索来源；仍需单独验收硬条件和配额，不因另一个插件已安装就判定组合需求通过。
